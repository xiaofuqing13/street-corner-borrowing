# 《街角借物所》产品与玩法提案

当前实现状态（2026-10-24）：首发已经完成；用户已批准v0.2六班十八目标、街坊事项、重排及新版插画界面。本文件下文保留首版设计过程，当前范围与验收以[09-v0.2完善计划.md](09-v0.2完善计划.md)及后续验收记录为准。

本文件是产品设计稿，不表示已实现、已测试通过或已具备发布条件。暂定名《街角借物所》也可在验证后调整。

## 1. 产品目标与核心乐趣

玩家在社区借物所值一班，面对邻居的借伞、借手推车请求，结合当前库存、公开归还时间和后续来访安排，决定现在借出还是婉拒。

核心乐趣是看懂周转关系、安排先后，让有限物品帮助更多邻居。每次选择都应能用眼前信息解释，不考验读速，不靠隐藏道德值或猜测作者意图。

首版采用单场景、单模式、有限回合的文字策略。场景、美术、短音效和人物反应用于表达借还与街坊生活；不加入查伪人、失物推理、自由探索、社区建设、商城或长期养成。

## 2. 首版范围与暂定数值

| 项目 | 首版提案，待确认 |
| --- | --- |
| 值班时段 | 16:00—19:00，游戏内时间，不对应现实等待 |
| 请求回合 | 16:00、16:30、17:00、17:30、18:00、18:30，共 6 回合 |
| 每回合请求 | 固定 2 条，按公开顺序逐条处理，共 12 条 |
| 物品 | 雨伞 2 把、手推车 1 辆；同类物品首版视为等价 |
| 人物 | 6 位常驻邻居，每位在示例班次提出 2 次请求 |
| 借用操作 | 查看信息后选择“借出”或“婉拒” |
| 成长与随机性 | 首版不设永久数值成长；排班固定，无随机违约 |
| 回合推进 | 当前两条请求处理完后由玩家点击进入下一时刻，无读秒压力 |

6 个半小时回合是游戏内班次结构，不是让玩家实际游玩 3 小时。现实单局时长需要试玩测量，暂不承诺具体分钟数。

固定排班用于先验证规则、UI 与周转策略。首版是否增加其他排班，须在核心体验验证后另行确认，不把追加内容视为已承诺范围。

## 3. 信息公开与“到访预告”

每条请求必须展示：邻居、所需物品、用途、借出时刻、确定归还时刻，以及当前可用数量。未来所有请求的到访时刻、物品、归还时刻和处理顺序均可查看；关键信息不能锁在广告后。

主称“到访预告”，不是已承诺的物品预约。它只表示邻居会在指定时刻提出请求，不提前占用库存，也不保证一定借到。界面应明确写出“到访时确认是否借出”，避免让玩家以为自己已承诺履约。

预告到时只转换成一条当前请求，不另外复制请求，也不自动借出。只有玩家对当前请求确认“借出”，才扣除一个库存并生成对应的待归还记录。同一请求只能被处理一次。

允许玩家提前查看预告并作计划；首版不提供提前承诺、预留库存、自动借出或超额预约。这些功能不是当前闭环的必要条件。

## 4. 时序与库存规则

每个回合严格按以下顺序推进：

1. 自动处理本时刻应归还的全部物品，增加可用库存，并给出明确的归还反馈。
2. 显示更新后的可用库存、在借记录和完整到访预告。
3. 处理本回合第 1 条请求，再处理第 2 条请求；确认一个决定后，库存立即影响后一个请求。
4. 两条均处理完后，玩家点击进入下一时刻。

借用期限以半小时为单位，归还时刻必须晚于借出时刻，且不晚于 19:00。首版归还严格按公开承诺发生，不发生随机晚还、丢失、损坏或临时延长。

当库存不足时，“借出”按钮不可用，并说明哪位邻居正在使用、何时归还；玩家仍可正常婉拒。超出收班期限的请求不进入首版排班。若后续内容配置误填了此类请求，应在内容校对中阻止其进入可发布版本，不能悄悄扣库存或改写归还时间。

18:30 的两条请求处理完后，推进至 19:00：先归还所有到期物品，再显示收班结算。19:00 不新增请求。若此时仍有在借物品，属于内容或逻辑错误，不应当作正常通关结果。

## 5. 选择、结束与重玩

借出应反馈邻居回应、物品去向和归还时刻；婉拒应有与当下情况相符的正常回应。玩家可以为后续需求保留库存，拒绝本身不扣“善良”“道德”或隐藏好感，也不安排羞辱、责备或突发惩罚。

暂定以“本班完成借用的次数”为主要服务结果，另外显示婉拒次数、帮助过的不同邻居人数和各类物品周转次数。这里的“完成借用”指已借出且归还；同一请求不能因归还或恢复存档被重复计数。

第一版不设突然破产、道德死亡或必须服务全部请求的硬失败。服务较少也会正常走到结算，给出可解释的结果；这属于策略反馈，不是假装已经达成高分。是否设置额外达标目标及其数值，待用户确认。

完整闭环必须包含：标题页 → 简短引导/规则说明 → 新值班或继续值班 → 逐条借用决策 → 自动归还与回合推进 → 19:00 清算 → 服务结果、个人纪录和完成反馈 → 再值一班或返回标题。

首版基础奖励是服务结果、邻居反馈、完成班次记录和个人最佳，不为了结算翻倍另造无用途货币。激励视频及其奖励由广告专项文档另行讨论；广告奖励不能与本文件的库存、时间、纪录规则发生冲突，也不应将基础信息或正常重开变成广告门槛。

## 6. 手算示例：前三回合

以下姓名、用途和排班均为规则演示，未获用户最终确认。初始可用：雨伞 2，手推车 1。

| 时刻 | 先发生的归还 | 当前请求与示例决定 | 处理后可用：伞 / 车 |
| --- | --- | --- | --- |
| 16:00 | 无 | 阿梅借伞至 17:00：借出；老周借车至 16:30：借出 | 1 / 0 |
| 16:30 | 老周还车，可用变为 1 / 1 | 小林借伞至 17:30：借出；陈叔借车至 18:00：借出 | 0 / 0 |
| 17:00 | 阿梅还伞，可用变为 1 / 0 | 小唐借伞至 18:00：借出；赵姨借车至 17:30：库存不足，婉拒 | 0 / 0 |

17:00 两条请求处理完：共处理 6 条，已借出 5 次、婉拒 1 次；已归还 2 次、尚在借 3 次。尚在借为小林的伞、小唐的伞、陈叔的车，因此伞库存 2 = 可用 0 + 在借 2，车库存 1 = 可用 0 + 在借 1。借出 5 = 已归还 2 + 在借 3。

后续到访预告中，阿梅将在 17:30 借车至 18:30。这条预告从开班就可见，但并未预留车。示例中车被陈叔借至 18:00，因此 17:30 仍无法借给阿梅。这是前一决策可以预见的代价，不是系统临时毁约。

若玩家在 16:30 婉拒陈叔，则 17:00 可把车借给赵姨；17:30 先收回赵姨的车，再决定借给阿梅。此对照只验证排期关系，不宣称已证明整班最优策略。整班排班、目标难度和多种策略是否有趣，仍待人工试玩验证。

## 7. 个人纪录与中途存档需求

个人纪录至少保存已完成班次数、当前排班的最佳完成借用次数，以及该次结算的基本统计。不同排班不得直接混为一个可比较的最佳纪录。若未来广告奖励会改变可用资源，应明确区分有辅助与无辅助成绩，具体规则随广告方案确认。

玩家在任一请求处理后、回合推进后退出，再次进入都应能继续当前班次。恢复内容至少包括排班标识、当前时刻、待处理请求位置、已处理请求、可用库存、在借及归还记录、累计统计和是否已经收班。

恢复不得重复借出、重复归还、跳过请求或再次写入同一班次的完成纪录。归还依据游戏内时刻，不因现实离线时长擅自改变班次。新开一班会影响现有中途进度时，必须先给出清楚的覆盖提示。

## 8. 内容一致性校对规则

- 每条请求具有唯一标识；预告、当前卡片、在借记录和结算均指向同一请求。
- 邻居身份、物品名称、借用用途与时间，在对话、信息栏和归还反馈中保持一致；不能口头说“半小时”却填写一小时。
- 每位邻居不得在同一时段重复借用同类物品；示例中再次来访必须与其已有借用状态相容。
- 同一时刻先还后借；第 2 条请求使用第 1 条处理后的库存；任何时刻可用与在借数量之和等于物品总量。
- 每条实际借用恰有一次归还；归还晚于借出且不超过 19:00；未借出的请求不得产生归还。
- 同一班次所有预告恰好各出现一次，正常流程共处理 12 条；19:00 只清算不产生第 13 条请求。
- 婉拒文案不暗示系统已承诺借出，不使用道德羞辱；借出文案不得承诺规则之外的奖励。
- 同样的排班与选择应产生同样的结果；不通过隐藏随机性制造广告需求。
- 图像表达的物品与规则一致；AI 生成的文字、数量、钟表读数不能作为精确游戏信息，精确信息由清楚可读的界面文字呈现。
