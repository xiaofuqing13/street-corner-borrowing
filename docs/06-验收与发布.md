## 2. 核心循环与规则

- [ ] 进入、理解目标、开始、六回合游玩、结算、重开和恢复记录形成完整闭环。
- [ ] 两类物品的名称、数量、当前可借库存、公开归还和到访预告时间能被准确理解。
- [ ] 玩家能够在决定前看到相关信息；不依赖隐藏事件或未说明的规则猜答案。
- [ ] 回合内先归还还是先借出有唯一规则，UI、数据与计算一致。
- [ ] 未到期的归还不能提前计入当前可借库存。
- [ ] 未来到访预告到时变成当前请求；请求处理、拒绝或错过后的状态与结果有明确说明。
- [ ] 预告不会自动扣库存、自动借出或产生未确认的库存保证。
- [ ] 六回合结束后有明确结算；不多出回合，19:00 完成归还清算且不再新借。
- [ ] 无广告路线可以完整结束，并能通过合理决策得到预期结果。
- [ ] 立即重开会清除上一局临时状态，保留哪些长期记录符合已确认规则。
- [ ] 新玩家能独立完成一局，并说明一次决定如何影响后续到访请求。
- [ ] 固定排班的内容量与首次完成后的重玩意愿经外部试玩验证；规则闭环通过不等于内容足够发布。

## 3. 库存、时间线与请求一致性

本次首发只有本所自有物品，不含广告奖励或外部临时调入。下列涉及临时物品的条件条目，本次注明“不适用：首发未启用”，后续若加入则单独验收，不记作已经通过。

- [ ] 对每一类物品分别检查库存，任何合法操作后均不为负数。
- [ ] 本所自有物品在“站内可借”和“已借出未归还”之间转移，到访预告不被误算成实体库存，也不提前扣库存。
- [ ] 已归还物品只入库一次；同一物品不能同时借给两个使用时间重叠的请求。
- [ ] 只有确认借出才扣库存；同一请求不能重复借出、重复扣库存或重复计入结算。
- [ ] 取消、切页、重复点击、返回及重新进入不重复执行借出或归还。
- [ ] 当前回合、请求处理时窗和归还时间的比较一致；边界时刻按已确认规则处理。
- [ ] 任何借出均满足同一 19:00 截止归还规则，不能因临时物品或广告放宽。
- [ ] 对没有可行排期的局面给出真实结果，不借用未来库存补账。
- [ ] 任何外部临时调入单独记录来源与流向，不混成本所固定资产。
- [ ] 若最终采用临时物品，其借出、归还或结算处置均有明确记录。

数量核对原则：按物品种类分别核算“初始站内数量＋实际归还＋外部调入－实际借出－退回外部”。该式需要与最终数据定义对齐，不能代替逐笔流水测试。自有资产与外部临时物品分别检查；到访预告只提供未来请求信息，不代表已承诺借出。

## 4. 存档与生命周期

## 5. 首发无广告核对与后续激励版本

按最新用户指令，本次首发核对以下事项；尚未实际检查时不提前勾选：

- [ ] 提交构建没有广告入口、广告播放请求、模拟广告成功或隐藏的激励发奖路径。
- [ ] 游戏资料中的“无广告、无内购”与实际提交版本一致。
- [ ] 基础玩法、必要信息、结算、重开及进度记录不因未开通广告而受限。

以下条目仅属于后续激励视频版本。本次标注“不适用：首发无广告”，不作为本次提审前置，也不将其记作已经实现或验证。后续须先确认奖励方案、核实当前项目配套文档和配置，再实施、真机验收并更新提审资料：

- [ ] 正常游戏、必要信息、结算和重开均不依赖广告。
- [ ] 只存在一个已确认的主动激励视频奖励，不包含自动弹出、插屏或 Banner。
- [ ] 点击前清楚说明物品、数量、目标当前请求及完整观看条件。
- [ ] 候选奖励只针对当前仍在合法处理窗口的现存请求，且满足 19:00 截止归还；不追溯修改已结束回合或错过的请求。
- [ ] 19:00 不通过广告新增借出或额外回合。
- [ ] 无有意义的补救对象时，不提供误导性的奖励入口。
- [ ] 连点不会产生重叠请求；次数与冷却按之后确认的数值执行，重开不能绕过应保留的限制。
- [ ] 完整观看按当前 SDK 的明确结果发奖，提前关闭不发奖。
- [ ] 重复、迟到或乱序回调不会重复发奖、跨局发奖或改变错误的借物请求。
- [ ] 奖励、库存流水与领取标记保持一致；中断恢复不会重复入账。
- [ ] 无广告、加载失败、展示失败和未收到结果时，游戏不会卡死，也不会伪造成功。
- [ ] 广告切后台、锁屏、返回、应用中断和再次启动的处理符合已核实的 SDK 语义。
- [ ] 预览模拟与真机真实广告被清楚区分；不能把模拟成功记作真实播放通过。
- [ ] 目标游戏、广告状态、广告位与本地配置逐项匹配；开通状态不被当作播放验证。
- [ ] 制造当前适用的审核要求已重新核对，不直接套用其他小游戏产品的限制。
